# Integrated Jev repository pilot — results

## Executive finding

**Plain pi completed both Fastify feature tickets and passed all measured behavior/type/regression checks. No Carthagent treatment completed a feature. The experiment does not establish Jev effectiveness: neither scored Jev cell reached plan inspection, so neither called Jev.** Three treatment runs ended on provider deadlines, one on a curl receive error. Treat those as unavailable/infrastructure outcomes, not comparative semantic quality scores.

The clear workflow observation is that treatment discovery consumed 19–54 tool starts without creating a plan. New compact delivery projections cannot help before a plan exists. Native compaction worked but repeatedly summarized growing discovery history. The next fix should target bounded discovery/plan startup and compaction reliability, not another larger task matrix or relaxed approval gates.

## Recommendation

Keep Jev built in and opt-in; do not advertise it as validated benefit. Pause broader paid benchmarking until an offline/cheap end-to-end fixture reliably goes from bounded discovery to plan approval, implementation, checks and final review with compaction. Investigate provider summarization deadlines without silently retrying unknown bills. Then run different held-out tickets with repetitions and the same compaction/network settings; add actual browser/API and permissioned live-research tracks on suitable infrastructure.

Practical observed outcome: **plain pi delivered both changes; Carthagent is not yet reliably reaching implementation on this setup.** Provider failures block a clean quality comparison, but they do not erase the costly pre-plan discovery behavior observed before failure.
