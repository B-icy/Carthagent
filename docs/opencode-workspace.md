# CTG native OpenCode orchestration

CTG's native workflow treats a task, worktree, and session as a durable logical unit. New task sessions are independent root sessions created with an explicit `location.directory`; CTG deliberately does not create OpenCode child sessions because native children inherit the parent's location. Each native worktree keeps its own `.harness` evidence naturally, while the project-level canonical checkout stores `.harness/opencode-tasks.json` as the task relationship and operation journal.

The `carthagent.workspace` RPC bridge runs inside the actual OpenCode plugin `Context`. The plugin API has no session-list operation: the server can inventory durable task sessions from task records and in-flight operation journals, then fetch each through native `session.get` and retain it only when its native project ID and location match the project root or that task's recorded worktree. This means the plugin RPC cannot enumerate untracked UI-created sessions; the native TUI client can and should combine its own global session list with this durable server snapshot. Session execution state is `running`, a native terminal outcome, `unknown` (no authoritative lifecycle information), or `unavailable` (the native record could not be fetched); task status never guesses idle from an absent outcome. The UI should use its native session status for ordinary sessions.

Delivery status reads `.harness/active.json` rather than selecting a report by modification time, validates the selected report, verifies that its run directory belongs to the requested session, and evaluates check receipts against the current source fingerprint and plan identity. Review is reported unavailable/stale when appropriate; starting a local review rechecks session ownership, snapshots exact local source, launches a location-bound reviewer, and persists the source-bound result. Native session status and execution lifecycle events emit the shared `updated` RPC event; only project-root and recorded task-worktree locations are accepted. Registration is awaited before the event listener starts, and cleanup aborts the stream and disposes the RPC. Legacy transcript import/export is not part of this RPC contract yet; the existing archive helpers are read-only and can be exposed after the shared contract is extended.

The native API requires `projectID` for worktree create/list/refresh/remove. Use `ctx.location.project.id` and `ctx.location.project.canonical`, the latter as the canonical plugin/configuration root. Live `session.*` and `worktree.updated` events are invalidation hints only: re-fetch native and CTG task state; do not treat events as durable state or replay missed events.

## Durable operations

Each create intent is persisted before calling the OpenCode APIs. Successful worktree + root session creation completes the journal entry and records the task. If the operation fails between native API calls, its intent remains `recovery-required`; reconciliation only repairs outcomes that can be verified and never blindly retries a worktree/session create. The JSON state is atomically replaced, and a cooperative exclusive lock serializes local CTG writers. A leftover lock is an explicit recovery condition, not an invitation to steal it automatically.

## Legacy Pi archive

Pi JSONL files are read-only archive inputs. Listing, searching, transcript display, and JSON/JSONL export are supported; malformed lines are reported with line numbers and valid records remain available. This code does not import, migrate, mutate, or resume archived sessions. All new work starts in a fresh OpenCode session.

## Reviews

Local delivery review and remote PR review are separate modes. Local delivery review snapshots the exact local diff and HEAD, opens a fresh explicitly located reviewer session, validates only the final assistant text plus a successful session outcome, and rechecks that both source and HEAD remain unchanged before admitting the result. Reviewer sessions use the registered native `build` agent by default with deny-all permissions followed by explicit read/glob/grep allows, blocking shell execution, edits, Code Mode, subagents, and skills. Review waits are abortable and default to a bounded five-minute timeout; cancellation uses the native `continue: false` interruption input and reports if interruption was not confirmed. Structured, validated findings are persisted in the review receipt. PR review queries GitHub via authenticated `gh api`, fetches the authoritative head/base refs into dedicated local refs, derives source from those exact Git objects, and re-fetches metadata and objects after review before recording a verdict. The repository and PR number are inputs; refs/source are never caller-supplied. GitHub CLI authentication is required. Existing `.harness/reviews` state via `lib/review-state.mjs` enforces the three-attempt limit. Neither mode pushes or merges. The default reviewer model is `lattice/gpt-6-luna` variant `high`, configurable by the service. No automatic merge permission is granted.

## Reusable module contracts

- `createTask({ ctx, projectID, canonical, task, from?, branch?, model?, agent? })` returns a persisted `{ id, task, projectID, canonical, worktree, sessionID, parentTaskID, status, createdAt }` task record.
- `listTasks({ canonical, includeOperations? })` returns the records, optionally with the operation journal.
- `listNativeSessions({ ctx, canonical, projectID })` verifies journaled root sessions using the supported `ctx.session.get` API; the plugin `Context` does not expose a session-list method. `listNativeWorktrees({ ctx, canonical, projectID })` uses only native `ctx.worktree.list({ projectID })` inventory.
- `reconcileTasks({ canonical, projectID, sessionIDs, worktreeDirectories })` returns `{ tasks, operations }` without retrying APIs, scoped to the native project ID. In-process pending operations remain pending during concurrent reconciliation; restart-interrupted operations are adopted only when both the native session and worktree inventories prove their completion.
- Archive exports: `listLegacyArchive({ roots })`, `searchLegacyArchive({ roots, query })`, `readLegacyTranscript({ path, roots })`, and `exportLegacyTranscript({ path, format?, roots })`. Reads require configured archive roots; symlink files/directories and real paths escaping roots are excluded or rejected.
- Review exports: `startReview({ ctx, cwd, identity?, model?, agent?, signal?, timeoutMs? })`, `startPullRequestReview({ ctx, cwd, repository, prNumber, model?, agent?, signal?, timeoutMs? })`, `createReviewSnapshot({ source, head })`, and `verifyPullRequestHeads({ localHead, remoteHead, pullRequestHead })`. PR metadata/source commands run via the real `gh` and `git` executables; there is no injectable production command runner. Reviewer agent defaults to the registered native `build` agent and is checked before session creation. Timeout defaults to 300000 ms (maximum 300000); caller cancellation and timeout abort native requests and attempt a bounded interrupt of an already-created reviewer.
- `registerOrchestration(ctx, options?)` in `plugins/carthagent/src/server/orchestration.ts` returns these operations in a server-oriented facade and an event `watch(signal)` invalidation stream.
