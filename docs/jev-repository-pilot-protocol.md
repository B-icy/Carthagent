# Fastify repository pilot protocol

Exploratory six-cell pilot, not a held-out repeated benchmark. Authorized by user to plan/implement/run. Total ceiling $15 ($14 candidates + $1 diagnostics), fresh campaign, unresolved reservations retained. Each cell $2.30 / 900s /120 admitted tools /100 paid requests including <=3 Jev, 16,384 output tokens, 400KB raw/402KB rebuilt input. No retry or post-evaluation repair.

## Selection and scope

Fastify v5.6.2, SHA `f15d4eaba03d86786bec2de7aed1236718c813f9`, MIT repository, 384 tracked files, 72,231 lines across tracked JS/TS (includes tests). Node26.7.0, pi0.85.1. Local dependency installation with scripts disabled, generated lock preserved and frozen. Full-stack commerce fixtures deferred due to machine capacity. Both tasks are additive library API maintenance: reply.appendHeader and reply.vary, requiring implementation, types, docs and regression tests. Exact acceptance in `tools/repo-pilot/tasks.mjs`.

Source: https://github.com/fastify/fastify/tree/f15d4eaba03d86786bec2de7aed1236718c813f9 . Author-created task contracts, not upstream tickets or claims these are desired upstream additions.

## Arms and order

append: plain -> harness -> Jev; vary: Jev -> harness -> plain. One replicate each; order partially balanced, no statistical efficacy claim. Same DeepSeek v4.1 flash/high through existing accounted gateway. Provider endpoint may vary; record it. Both Carthagent arms use new compact context; Jev arm uses **production built-in delivery flags**, not benchmark advisor.ts. No old-harness ablation, no causal attribution of context improvements versus changed tasks.

Same native compaction configuration in every candidate: enabled, 100k configured context, reserve70k/keepRecent6k (threshold30k). No custom model summarizer. Smoke uses lower threshold solely to demonstrate native compaction. All summarization paid requests charged to corresponding account.

## Documentation track

Official Node22.19 HTTP markdown and RFC9110 fetched over HTTPS, frozen with URL/SHA receipts, mounted read-only at /reference identically. Model uses normal read/grep before approval, avoiding a custom read-only tool bypass. This tests **frozen online-documentation use**, not live unrestricted web search. No web research superiority claim.

## Isolation

Unprivileged extracted Ubuntu bubblewrap0.6.1, no system installation. New user/PID/network/IPC/UTS namespaces, all capabilities dropped, private proc/dev/tmp, read-only engine/harness/dependencies/reference mounts, only candidate workspace/config/session/logs writable. Host home/auth, supervisor tests/reference patch, other runs and original repository are not mounted. Tested inaccessible paths explicitly. Network namespace has only loopback; local Unix-socket relay exposes accounted generator/Jev broker endpoints. No Internet/production service credentials passed. This is stronger isolation than historical same-user cwd separation, but not a formal adversarial sandbox security audit; shared kernel and broker are trusted. No cgroup RAM/CPU limit; one sequential run and supervisor deadline/process-group cleanup.

## Evaluation and readiness

Protected external evaluator mounted only after candidate termination. Seven runtime categories per task: order/normalization, raw-state compatibility, special header semantics, arrays/no-op, atomic invalid calls, real HTTP onSend/plugin integration, request independence. Supervisor reference patches: 7/7 each; unmodified base1/7 each; overwrite/case-sensitive mutants3/7 and5/7. Relevant original tests mounted read-only for evaluator regression execution, preventing candidate weakening. Original test files still writable while developing; diff reports modifications. Full upstream suite/type suite may be candidate-run; disclose what actually ran.
